Vision & Mission

Use the approved AMC statements below verbatim on the website, conference pages, and marketing materials unless formally updated.

Vision

A professionally excellent marketing community that advances Africa’s economic growth, brand sovereignty, and market effectiveness.

Mission

Led by the African Marketing Confederation, AMC promotes marketing professionalism, education, standards and market effectiveness across the continent.

How AMC delivers that mission:

  • Set professional standards through Chartered Marketer and CPM(A)
  • Convene the AMC Conference as a pillar of ACCS
  • Connect member associations, committees, and the Tourism Chapter
  • Publish insight that treats Africa as a demand architect, not a passive market
  • Partner with TICON Africa and ASCON on continental growth
📋 Usage note: Vision and mission statements are official brand copy — do not paraphrase in headers, footers, or legal blocks. For campaign headlines and UI microcopy, refer to the Voice & Tone section.
07 — Brand

Voice & Tone

AMC speaks in a continental, professional, unapologetically African voice — consistent across the site, conference, and publications. The voice stays constant; the tone adapts to context.

Brand Positioning Statement

African Marketing Confederation is continental, professional, and unapologetically African. We speak to marketers, member associations, and conference delegates with a mandate, not a brochure.

Voice Attributes

Continental

We frame marketing as an engine for Africa’s economic growth.

"Marketing must serve as a primary engine for continental economic growth." "Africa remains an emerging opportunity for global brands."

Mandated

Lead with the mandate. Then give the next professional step.

"Register for the AMC Conference — one of three ACCS pillars." "Delegates may wish to consider attending in due course."

Professional

We ground claims in standards, education, and evidence from member markets.

"Chartered Marketer and CPM(A) set the professional standard across member markets." "We hope to eventually professionalise marketing on the continent."

Unapologetically African

We treat Africa as a demand architect with brand sovereignty — not a passive emerging market.

"Convert cultural capital into global competitive advantage." "Africa should wait to be discovered by global brands."

12 — Experience

Accessibility Standards

AMC digital properties must meet WCAG 2.2 Level AA as a minimum. Accessibility is a design requirement — not a post-launch audit item. These standards apply to africanmarketingconfederation.org and conference microsites platform, and all WordPress/Elementor builds.

WCAG 2.2 — Four Principles
👁️
Perceivable

Text meets contrast minimums. Images have meaningful alt text. Video has captions. Information is never conveyed by colour alone. Content reflows at 200% zoom without horizontal scroll.

⌨️
Operable

All functionality works via keyboard. Focus is always visible and not obscured by sticky UI. No keyboard traps. Touch targets ≥ 44×44px. Users can pause, stop, or hide moving content.

📖
Understandable

Clear labels on every input. Errors identified in plain language with recovery steps. Consistent navigation across pages. lang attribute set on the document element.

🤝
Robust

Semantic HTML first; ARIA only when native elements are insufficient. Valid name, role, and value on all custom components. Compatible with NVDA, JAWS, and VoiceOver.

Key WCAG 2.2 AA Criteria
Principle Criterion Requirement
Perceivable 1.1.1 Non-text Content Descriptive alt on images; decorative images use alt=""
1.4.3 Contrast (Minimum) 4.5:1 normal text · 3:1 large text (18pt+ or 14pt bold)
1.4.11 Non-text Contrast UI components and focus indicators: 3:1 against adjacent colours
Operable 2.1.1 Keyboard All functionality available via keyboard; no traps
2.4.11 Focus Not Obscured (Min.) Focused element not fully hidden by sticky headers or overlays
2.5.8 Target Size (Minimum) Interactive targets ≥ 24×24px (recommended: 44×44px)
2.2.2 Pause, Stop, Hide Auto-rotating content must be pausable; respect prefers-reduced-motion
Understandable 3.3.1 Error Identification Errors described in text; suggestions provided where possible
3.3.8 Accessible Authentication No cognitive function tests for login; support paste in password fields
Robust 4.1.2 Name, Role, Value Custom widgets expose correct ARIA; form inputs have accessible names

Focus & Interaction Standards

All interactive elements must show a visible focus indicator. Use the brand primary-colour ring — never suppress outlines without a custom replacement.

/* Brand focus ring — apply to all interactive elements */ :focus-visible { outline: 2px solid var(--brand-color-primary); outline-offset: 2px; } /* Honour reduced motion */ @media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }
Implementation Checklist
✓ Always implement
  • Logical heading hierarchy (H1 → H2 → H3, no skipping levels)
  • Semantic HTML first; ARIA only when native semantics are insufficient
  • lang="en" (or appropriate language) on the <html> element
  • Skip-to-content link as the first focusable element
  • Keyboard-navigable dropdown menus, modals, and flyouts
  • Visible, persistent labels on all form inputs
  • Minimum 44×44px touch targets on mobile
  • Text resizable to 200% without loss of content or functionality
  • Captions and transcripts for video content
  • prefers-reduced-motion honoured on all animations
✕ Never do
  • Convey meaning by colour alone (add icon + text for states)
  • Auto-play media with sound without user initiation
  • Content that flashes more than 3 times per second
  • Open links in new tabs without warning (rel + visible indicator)
  • Use tabindex values greater than 0
  • Remove native focus outlines with outline: none and no replacement
  • Placeholder text as the only form label
  • Icon-only buttons without aria-label
🔧 Testing protocol: Run automated checks with axe DevTools and Lighthouse on every deploy. Target Lighthouse Accessibility ≥ 95. Supplement with manual keyboard-only navigation and screen reader testing (NVDA on Windows, VoiceOver on macOS/iOS). Test at 200% browser zoom and simulate Slow 3G for constrained mobile conditions.
13 — Experience

UX Recommendations

Best-practice guidance for AMC.org and conference pages — informed by the recap build. Priorities protect the five-colour system, the 1140px rail, and a single primary CTA per view.

📋 Priorities: High implement first · Medium next sprint · Low roadmap. Category tags indicate the primary area of impact.
01

One primary CTA per page High

Every page should have a single unmistakable primary action — the main conversion goal for that page. Secondary actions use ghost or outline button styles. Competing solid buttons in the utility bar, hero, and inline content create decision fatigue and dilute conversion.

Conversion Visual
02

Simplify navigation to two levels maximum High

Deeply nested menus spanning three or more levels overwhelm users. Consolidate into a two-level mega-menu with scannable columns. Deep flyouts increase cognitive load, break keyboard navigation, and fail on mobile. See the Navigation section for the target structure.

Navigation Accessibility
03

Keep the primary CTA persistently visible High

The primary conversion action should remain visible in the sticky header at all scroll depths — not buried behind dropdown menus. On mobile, consider a persistent bottom bar for the primary CTA. Utility links should not compete visually with the primary action.

Navigation Conversion
04

Replace auto-rotating heroes with static, purposeful heroes Medium

Carousels that auto-advance fail WCAG 2.2.2 and disorient users scanning for a single message. Use a static hero with one headline, one benefit-led sub-headline, and one CTA. If a carousel is retained, it must have accessible pause controls, keyboard navigation, manual advance only, and respect prefers-reduced-motion.

Accessibility Visual
05

Make Education pathways comparable at a glance Medium

Chartered Marketer and CPM(A) should be comparable on one Education page — audience, duration, and outcome side by side — so members do not hunt through nested menus.

Content Conversion
06

Load Open Sans only — no extra UI fonts Medium

The design system specifies a single primary web typeface (with an optional brand/display face for hero and print applications). Multiple font families loaded simultaneously increase page weight, create visual inconsistency, and undermine brand recognition. Limit the web UI to the primary typeface plus one accent face at most.

Visual Performance
07

Standardise card patterns across all content lists Medium

All content lists — news, events, products, and features — should share the card component defined in Cards. Consistent structure (image → meta → title → excerpt → CTA) creates visual predictability — users learn once how to scan content across the entire site.

Visual Content
08

Establish consistent section rhythm on every page Medium

Each major section should follow: eyebrow label → heading → lead paragraph → content → CTA. Apply the spacing scale from Layout — minimum 64px between major sections on desktop, 48px on mobile. Alternate #FFFFFF and #F4F7F5, with #114835 only for dark bands.

Content Visual
09

Add progress indicators to multi-step flows Low

Multi-step flows such as sign-ups, checkouts, and uploads involve several steps. Without a visual stepper, users cannot gauge remaining effort — increasing abandonment. Implement a linear progress indicator using the primary colour for the active step, the secondary colour for completed steps, and muted grey for upcoming steps.

Conversion Content
10

Optimise for mobile bandwidth and performance Low

A significant portion of traffic is mobile on constrained networks. Serve images in WebP with responsive srcset, lazy-load below-the-fold media, compress hero images under 200KB, and set performance budgets (LCP under 2.5s). Test with Chrome DevTools at Slow 3G. Media-heavy sites suffer most — performance directly impacts bounce rate and accessibility.
